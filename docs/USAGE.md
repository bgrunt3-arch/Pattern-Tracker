# COCOcase レビューアプリ 使い方ガイド

**URL**: https://cococase-app.vercel.app

AirPods Pro 3 ケース 605 デザインの採用・不採用を判定するアプリ。

---

## 画面構成

| 画面 | パス | 用途 |
|------|------|------|
| カタログ | `/catalog` | 605 デザインを一覧して個別に判定 |
| レビュー | `/review` | カード型 UI で素早く 1 枚ずつ判定 |

右上の `✓✗ REVIEW` ボタンで切り替え。

---

## 1. カタログ画面（ /catalog ）

### フィルター

**採用状態フィルター（左側）**

| ボタン | 表示対象 |
|--------|---------|
| `ALL` | 全 605 件 |
| `✓ 採用` | 採用済みのみ |
| `− 未` | 未判定のみ |
| `✗ 不採用` | 不採用のみ |

**カテゴリフィルター（右側）**

`ALL` / `FLORAL` / `MARBLE` / `ANIMAL` / `FOOD` / `BOTANICAL` / `GEOMETRIC` / `ABSTRACT` / `VINTAGE` / `CELESTIAL` / `COASTAL` / `JAPANESE` / `OUTDOOR` / `WESTERN` / `ROMANCE`

横スクロールで全カテゴリにアクセスできる。

### 検索

左上の `Search...` ボックスでデザイン名を部分一致検索。

### カードの操作

- 各カード下部の `✗`（赤）= 不採用 / `✓`（緑）= 採用
- 既に判定済みのカードは `✓ 採用済み・解除` / `✗ 不採用済み・解除` をクリックで取り消し
- カード本体をクリックするとモックアップが拡大表示
  - 一部のデザイン（pos01・pos02 両方を持つもの）は左右の矢印で切り替え可能

---

## 2. レビュー画面（ /review ）

未判定デザインを 1 枚ずつ表示。テンポ良く判定したいときに使用する。

### 操作

| アクション | 結果 |
|-----------|------|
| 左にスワイプ / `✗` ボタン | 不採用 |
| 右にスワイプ / `✓` ボタン | 採用 |
| `↩︎` ボタン | 直前の判定を取り消し |

### 上部のステータス表示

- `採用 / 未 / 不採用` の件数が表示される
- **数字をクリックすると、その状態だけのカタログ画面にジャンプする**

### フィルター

- `未`（デフォルト）：未判定のみ
- `すべて`：判定済みも含めて表示

---

## 3. データの保存

判定結果は**自動でクラウドに保存**される。

- 別端末からアクセスしても同じ状態が反映される
- ネット接続が必須
- 右上に同期エラーが出た場合はページをリロード

---

## 4. 効率的なレビューの流れ

### A. 一気に判定する場合
1. `/review` を開く
2. スワイプまたはボタンで判定し続ける
3. 全件終了したら未判定リストが空になる

### B. カテゴリ別に判定する場合
1. `/catalog` でカテゴリ（例: FLORAL）を選択
2. 該当カテゴリのみ表示
3. 各カードで判定
4. ステータスバーから切替先 → 別カテゴリへ

### C. 判定し直す
1. ステータスの数字（`採用` 等）をクリック
2. 採用済みのみ表示
3. 個別に「解除」をクリックで未判定に戻る

---

## 5. 動作環境

- **PC / モバイル両対応**
- スワイプはタッチ・マウスドラッグ両方可能
- 採用 / 不採用は何度でも変更可能

## 画質について

### 現在の仕様

モックアップ画像は **JPEG（品質 85%）/ 約 165 KB / 枚** で配信されている。

### なぜこの仕様か

ストレージサービス（Vercel Blob）の **Hobby プランが 1 GB 上限** のため。

| 形式 | 1枚あたり | 600枚合計 | 1GB プランで収まるか |
|------|----------|----------|----------------------|
| PNG（無圧縮相当） | 30 MB | 17.9 GB | ❌ 18 倍オーバー |
| PNG 最適化（pngquant） | 5 MB | 3 GB | ❌ 3 倍オーバー |
| **JPEG 85%（現状）** | **165 KB** | **約 100 MB** | ✅ 10% で余裕 |
| JPEG 95% | 400 KB | 約 240 MB | ✅ 24% |
| JPEG 100% | 800 KB | 約 480 MB | ✅ 48% |

モックアップは「白背景 + 3D の連続的な陰影」というグラデーション主体のため、JPEG 圧縮の劣化が目立ちにくく、実用上は 85% でも PNG とほぼ区別できない。

### 高画質化の選択肢

#### 選択肢 1: JPEG の品質を上げる（最も簡単・無料）

`scripts/upload-mockups-to-blob.ts` の品質設定を変更し、再アップロードする。

```typescript
const JPEG_QUALITY = 85;  // → 95 や 100 に変更
```

**手順:**
1. 上記ファイルを編集
2. `npx tsx scripts/clear-blob-mockups.ts --prod` で本番 Blob をクリア
3. `rm public/mockup-urls.json` で manifest をリセット
4. `npx tsx scripts/upload-mockups-to-blob.ts --prod` で再アップロード
5. Vercel が自動で反映

**目安:**
- 品質 95% → 240 MB（推奨）
- 品質 100% → 480 MB（PNG とほぼ等価）

どちらも Hobby プランの 1 GB 内に収まる。

#### 選択肢 2: Vercel Blob を Pro プランへ（PNG をそのまま配信）

- 月額 **$10**（約 1,500 円）で 1 TB
- PNG 17.9 GB がそのまま入るので**無圧縮配信が可能**
- Pro 化したあと、`scripts/upload-mockups-to-blob.ts` の JPEG 変換処理を外し、PNG のままアップロードする実装に変更する

#### 選択肢 3: 別ストレージ（Cloudflare R2 / AWS S3）+ PNG

- **Cloudflare R2**: 10 GB 無料（毎月）
- **AWS S3**: 5 GB 無料（最初の 12 ヶ月）

PNG をそのまま配信したい場合の最も安価な方法。実装には：

1. R2 / S3 アカウント作成 + バケット作成
2. アクセストークン取得
3. `scripts/upload-mockups-to-blob.ts` を S3 互換 API に書き換え
4. `app/api/mockup/[...path]/route.ts` を R2 / S3 から取得するように変更

切替工数は **1〜2 時間**。

### 推奨

カタログ表示用の画質としては **JPEG 95% への変更** で必要十分。
クライアント納品物として原寸 PNG が必要な場合のみ、選択肢 2 か 3 を検討。

## 補足

### モックアップ画像の生成

開発側のメモ。ローカルで再生成する場合の手順:

1. **パターンタイル生成**: `npx tsx scripts/tile-patterns.ts`
2. **Photoshop バッチ**: `npx tsx scripts/generate-mockups-photoshop.ts`
   - Photoshop 2026 が必要
   - scratch disk は外付け SSD を推奨（930 GB 確保）
   - チャンクサイズ 50 で約 12 分で 600 枚生成可能
3. **Vercel Blob にアップロード**: `npx tsx scripts/upload-mockups-to-blob.ts --prod`

### 環境変数

`.env.local` に必要な変数:
```
BLOB_READ_WRITE_TOKEN=<vercel から取得>
BLOB_ACCESS=private
```
